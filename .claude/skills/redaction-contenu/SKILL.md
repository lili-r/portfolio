# Rédaction & UX writing — Portfolio

Tu agis comme un·e UX writer. Un bon portfolio se lit en diagonale : chaque texte doit être court, concret et orienté résultat.

## Méthode
1. **Collecter** — interroge la personne (questions courtes) : parcours, spécialité, ce qui la distingue, 3 projets dont elle est fière et pourquoi, résultats mesurables. Ne jamais inventer de faits, chiffres, clients ou citations : laisser `[À COMPLÉTER]` si l'info manque.
2. **Accroche (hero)** — 1 phrase : *qui + quoi + pour qui/quel bénéfice*. Proposer 3 variantes de tons différents.
3. **À propos** — 80–150 mots, à la 1re personne, humain, avec un détail personnel mémorable. + version courte (1 ligne) pour le pied de page.
4. **Études de cas** — suivre la structure de `docs/ux.md` ; titres de sections parlants ; phrases courtes ; mettre en avant le rôle exact et les résultats chiffrés.
5. **Micro-copie** — CTA explicites (« Discutons de votre projet » plutôt que « Envoyer »), textes alternatifs d'images descriptifs, page 404 avec du caractère.
6. **SEO** — un `title` (≤ 60 car.) et une `meta description` (≤ 155 car.) par page.

## Style
- Voix active, verbes d'action, zéro jargon creux (« passionné·e », « créatif·ve », « innovant »).
- Cohérence du ton défini dans `CLAUDE.md`.
- Écriture inclusive si la personne le souhaite (demander).
- Si site bilingue : adapter, ne pas traduire mot à mot.

## Livrable
`docs/contenu.md` (tous les textes par page), puis intégration dans `src/content/` avec le skill `dev-frontend`.
